# Visual Layout Principles｜英语思维视觉排版准则

本文件定义 English Thinking Word Explainer 在网页、复习卡、知识图卡、可视化笔记中的内容组织与排版规则。

## 第一硬规则：视觉分组必须服从内容关系

> **视觉分组必须服从英语思维里的内容关系，而不是服从原始 Markdown 的换行。**

Markdown 的换行、空行、列表符号和代码块只是原始存储格式，不能直接决定网页中“拆几张卡”“分几行”“是否并列”。

在排版之前，必须先理解内容之间是什么关系，再选择视觉结构。

## 先理解，再排版

任何内容进入可视化界面前，先判断它属于哪一种关系：

1. **同一场景链**：小标题 → 例句 → 解释 → 图示 → 同类例子。
   - 必须放在同一个场景卡中。
   - 不得因为 Markdown 换行把“地图 / station / ● me”等图示内部元素拆成多张卡。

2. **因果 / 生长链**：核心 → 物理意义 → 日常意义 → 抽象意义 → 固定结构。
   - 使用流程、箭头、层级树或步骤卡。
   - 不要把每一行变成无关系的独立白框。

3. **对比关系**：A vs B、错误 vs 正确、不同镜头。
   - 使用左右对比、上下成对或同场景双镜头。
   - 对比项必须在同一视觉区域内出现。

4. **并列关系**：多个高频搭配、多个代表例句、多个同类场景。
   - 才可以拆成独立小卡、标签或列表。
   - 一项一组，保持相同层级。

5. **从属关系**：解释属于某个例句、图示属于某个场景、注意事项属于某个规则。
   - 从属内容必须贴近其上位内容，不能被拆到远处。

6. **知识树关系**：已学概念之间的节点连接。
   - 使用节点 + 连线 / 箭头 / 分支。
   - 不用连续长段文字代替结构关系。

## 三层学习界面的排版标准

### 第一层｜3 秒复习

目标：3 秒内恢复核心模型。

只保留：
- 核心画面
- 一句话本源
- 记忆钩子

优先级：画面 > 关键词 > 中文说明。

### 第二层｜快速理解

目标：快速知道“怎么用”。

按内容关系组织：
- **核心使用场景**：一个场景一个完整语义组，内部顺序为“小标题 → 英文例句 → 英语思维解释 → 图示 → 同类例子”。
- **高频结构**：结构名与含义成对，不拆散。
- **代表例句**：真正并列的例句才一例一卡。

### 第三层｜深度学习

目标：看懂“为什么”和“与其他知识如何连接”。

必须按逻辑关系可视化：
- **底层英语思维**：总原则 → 关键判断点 / 镜头，不按句号或换行切卡。
- **意义如何生长**：核心 → 具体 → 日常 → 抽象 → 结构，使用生长链 / 箭头。
- **易混词对比**：把需要比较的词放在同一组，用同一生活场景或同一坐标系比较。
- **英语思维避坑**：❌ 错误模型 与 ✅ 更稳模型必须成对出现；补充边界紧跟在对应规则后。
- **知识树连接**：节点 + 关系，优先用 AT / ON / IN、TO / INTO 等可见连接，而不是长文堆叠。

## 文本排版规则

- 英文关键词是视觉锚点，中文负责解释。
- 标题靠字号、留白、颜色建立层级，不靠一味加粗。
- 该分行时分行，但“分行”不等于“分组”。
- 同一语义单元内部允许多行；不同语义单元才考虑不同卡片。
- ASCII 图、箭头图、容器图视为一个不可拆视觉整体。
- 不把 `text`、Markdown 标记、`###`、代码围栏等源格式直接显示给学习者。
- 一屏优先呈现关系，不优先呈现字数。

## 排版前自检

在生成任何复习网页或知识卡之前，检查：

- [ ] 我是否先理解了内容关系，再决定分组？
- [ ] 是否把同一场景的例句、解释、图示放在一起？
- [ ] 是否错误地把 Markdown 换行当成卡片边界？
- [ ] 生长关系是否用流程/箭头呈现？
- [ ] 对比项是否在同一视觉区域？
- [ ] 错误与正确模型是否成对？
- [ ] 图示内部元素是否保持完整？
- [ ] 英文关键词是否比中文解释更容易扫到？
- [ ] 用户能否不读完整段落也看懂主要关系？

## 最终原则

> **先理解内容关系 → 再选择视觉结构 → 最后决定换行、卡片与样式。**

视觉设计服务于英语思维关系，不服务于 Markdown 源格式。
