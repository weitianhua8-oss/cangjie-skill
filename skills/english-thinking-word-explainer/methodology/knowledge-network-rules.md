# 英语思维知识网络准则

本文件定义 `english-thinking-word-explainer` 的知识网络构建规则。它适用于复习网页、知识图卡、总知识地图以及后续新增词汇/语法结构。

## 1. 总原则

> **知识网络不是“相关词列表”，而是“有类型、有方向、有理由的概念关系图”。**

任何两个节点之间都不能因为“看起来有关”就连线。每一条边必须回答三个问题：

1. **为什么连？**
2. **是什么关系？**
3. **方向从哪里到哪里？**

如果不能明确回答，就不连。

同时遵守视觉总准则：

> **视觉分组必须服从英语思维里的内容关系，而不是服从原始 Markdown 的换行。**

Markdown 的换行只负责文本可读性，不能决定知识节点、卡片或连线边界。

---

## 2. 知识网络的四种正式关系

### A. 上位系统 `SYSTEM`

说明当前知识点属于哪个更大的英语认知系统。

示例：

- AT → 空间与定位系统
- TO → 方向与目标系统
- BE → 状态系统
- SEE / LOOK / WATCH → 视觉感知系统

规则：

- 上位系统必须是比当前词更抽象的概念类别。
- 不把另一个普通单词冒充成“上位系统”。
- 同一批兄弟节点应尽量共享稳定的大系统，而不是每个词单独造一个系统名。

---

### B. 直接生长 `GROWTH`

表示某个高频用法或结构可以从当前核心本源**直接自然长出**。

方向：

`核心节点 → 直接生长结构`

示例：

- TO → `FROM...TO...`
- TO → `TO DO`
- ON → `TURN ON`
- GET → `GET + adj`

判断标准：

- 去掉当前核心概念后，这个结构的解释会明显缺一块。
- 能用当前核心画面自然解释，不需要借助另一个完整核心节点才能成立。

不要把以下内容误标为直接生长：

- 只是易混的词
- 只是同主题词
- 必须由两个独立核心共同贡献才成立的结构

---

### C. 组合关系 `COMBINATION`

表示两个或多个独立核心节点组合后，生成一个更完整的新结构或新画面。

形式：

`A + B → C`

示例：

- IN + TO → INTO
- TOO + TO → TOO...TO...
- LOOK + AT → LOOK AT
- BE + V-ing → 进行中的动作状态

规则：

- 必须能说明每个组成部分分别贡献什么。
- 组合结果不能只写中文翻译，要写“组合后的英语思维画面”。
- 如果一个结构只是固定搭配、但无法可靠拆出各部分贡献，就不要强行画组合关系。

---

### D. 易混对比 `CONTRAST`

表示两个概念经常出现在相似场景里，但说话人选择了不同镜头。

形式：

`A ≠ B`

对比关系通常是**双向的**，但每个节点页面的解释可以不同。

示例：

- TO ≠ AT：朝目标移动 ≠ 锁定目标点
- IN ≠ INTO：内部关系 ≠ 跨界进入
- ON ≠ IN：接触面 ≠ 内部容器
- SEE ≠ LOOK ≠ WATCH：收到画面 ≠ 主动转视线 ≠ 持续跟随变化

规则：

- 只有学习者真实容易混淆时才建立。
- 必须写清“同一场景下镜头差异”。
- **易混对比绝不能显示成兄弟派生或直接生长。**

---

## 3. 禁止使用模糊关系

默认禁止以下标签：

- 相关节点
- 相关词
- 兄弟词（除非确实只是 UI 分组，不作为语义边）
- 有联系
- 延伸词

原因：这些词没有说明“为什么相关”。

知识网络中必须优先落到：

`SYSTEM / GROWTH / COMBINATION / CONTRAST`

如果四类都不合适，则宁可不连。

---

## 4. 网络构建顺序

每新增一个知识点，按以下顺序建网：

1. **先确定核心本源**：没有稳定核心，不建网。
2. **确定上位系统**：它属于哪个更大的认知系统？
3. **找直接生长**：哪些高频结构直接从核心长出？
4. **找组合关系**：它和已学节点组合后产生什么？
5. **找易混对比**：同场景下最容易和谁混？
6. **删除模糊连接**：凡是说不清关系类型的边全部删除。
7. **检查方向**：生长和组合有方向；对比通常双向。
8. **控制数量**：复习卡只保留最重要关系，总知识网络可展开更多。

---

## 5. 卡片小网络与总网络的职责

### 卡片里的“小知识网络”

目标：快速理解当前词。

最多优先显示：

- 1 个上位系统
- 2–4 个直接生长
- 1–3 个组合关系
- 1–3 个易混对比

不要为了“显得丰富”塞满连线。

### 独立“总知识网络”

目标：探索整个英语底层系统。

必须支持：

- 按上位系统浏览
- 点击节点查看四类关系
- 从关系节点跳到对应学习卡
- 同一关系类型使用固定视觉编码

---

## 6. 视觉编码规则

推荐固定编码：

- `SYSTEM`：系统标签 / 顶部父节点
- `GROWTH`：`↓` 或单向箭头，绿色系
- `COMBINATION`：`＋`，蓝色系
- `CONTRAST`：`≠`，暖色系

颜色只能辅助，不能成为唯一信息载体；必须同时显示关系名称或符号。

禁止：

- 用同一种线表示所有关系
- 把对比词放在“直接生长”下面
- 把组合结构误画成父子关系
- 因 Markdown 换行把一个完整图示拆成多个节点

---

## 7. 关系判定示例：TO

核心：

> TO = 朝目标伸出的箭头。

正确网络：

### SYSTEM

`TO → 方向与目标系统`

### GROWTH

- TO → `FROM...TO...`：起点 → 终点
- TO → `TO DO`：当前状态 → 动作目标
- TO → `LEAD TO`：路径 → 结果终点

### COMBINATION

- IN + TO → INTO：朝内部并跨过边界
- TOO + TO → TOO...TO...：程度越界 → 目标动作受阻

### CONTRAST

- TO ≠ AT：朝目标移动 ≠ 锁定目标点
- TO ≠ FOR：方向/传递 ≠ 面向/服务于
- TO ≠ INTO：只指向目标 ≠ 跨界进入内部

AT 可以出现在 TO 的网络中，但只能放在 `CONTRAST`，不能作为 TO 的直接生长或“兄弟派生”。

---

## 8. 质量自检

每次生成或更新知识网络前检查：

- [ ] 当前节点的核心本源是否稳定？
- [ ] 上位系统是否真的更抽象，而不是另一个普通词？
- [ ] 每条 `GROWTH` 是否能从核心自然长出？
- [ ] 每条 `COMBINATION` 是否说明了各部分贡献？
- [ ] 每条 `CONTRAST` 是否来自真实易混场景？
- [ ] 是否存在“只是有关”但说不清关系的连接？有则删除。
- [ ] 是否把对比误画成派生？
- [ ] 是否把组合误画成父子？
- [ ] 是否因为 Markdown 换行错误拆组？
- [ ] 小网络是否保持简洁，能在数秒内看懂？

## 最终公式

> **先定核心 → 找系统 → 看生长 → 看组合 → 做对比 → 删除模糊边 → 再视觉化。**
